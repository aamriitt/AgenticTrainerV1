# 01 System Overview

## 1. Business Problem
In many enterprises, Subject Matter Expert (SME) knowledge is scattered across various formats: videos, meeting transcripts, PDF manuals, internal FAQs, runbooks, and architecture documents. As organizations scale, this knowledge becomes siloed and difficult to access. Traditional search engines only retrieve links to documents, while basic chatbots often hallucinate or provide answers without verifiable context. This leads to reduced productivity, duplicated effort, and a high barrier to entry for new employees seeking contextual answers.

## 2. Objectives
The **Agentic Trainer** aims to bridge this gap by transforming static enterprise knowledge into an interactive, intelligent multi-agent assistant. The primary objectives are:
- **Contextual Reasoning:** Provide highly accurate answers based strictly on ingested SME knowledge rather than generic internet data.
- **Traceability:** Every claim or answer generated by the system must include precise citations back to the original source material.
- **Continuous Learning:** Allow SMEs and users to provide feedback, flag inaccuracies, and update the knowledge base dynamically without requiring complete system retraining.
- **Agentic Collaboration:** Utilize a multi-agent architecture where specialized agents handle intent recognition, retrieval, reasoning, and citation, ensuring high reliability.

## 3. Scope
**In Scope:**
- Ingestion of videos, PDFs, text files, and transcripts.
- Multi-agent orchestration using LangGraph.
- Retrieval-Augmented Generation (RAG) using ChromaDB and embedding models.
- Audio/Video transcription using Whisper.
- A FastAPI backend providing RESTful endpoints for chat and management.
- Integration with Gemma 3 (via Ollama) as the core language model.

**Out of Scope (Non-Goals):**
- Acting as a general-purpose conversational AI for non-business topics.
- Direct execution of system commands or runbooks (this is a knowledge-retrieval system, not an automation tool).
- Fine-tuning of the foundational Gemma 3 model (knowledge is updated via RAG, not weight updates).

## 4. Terminology
- **Orchestrator Agent:** The central controller that routes tasks to specialized sub-agents based on the user's input.
- **SME (Subject Matter Expert):** The individual whose knowledge is being captured and queried.
- **RAG (Retrieval-Augmented Generation):** The process of fetching relevant documents from a vector store to ground the LLM's response.
- **ChromaDB:** The vector database used for storing and retrieving document embeddings.
- **LangGraph:** The framework used to manage state and define the flow between the multi-agent system.
- **Whisper:** The speech-to-text model used to transcribe video and audio knowledge sources.
- **Gemma 3:** The foundational large language model powering the agents' reasoning capabilities.

## 5. Example Workflow
To understand how the Agentic Trainer operates, consider the following interaction:

1. **User Query:** A user asks, "How do we deploy the billing service in the new environment?"
2. **Intent Recognition:** The Orchestrator routes the query to the Intent Agent, which classifies it as a `HOW_TO` query requiring technical runbook knowledge.
3. **Retrieval:** The Retrieval Agent converts the query into embeddings and queries ChromaDB. It retrieves snippets from a video transcript ("Billing Service Walkthrough by John Doe") and a PDF ("Deployment Runbook v2").
4. **Reasoning & Synthesis:** The Reasoning Agent receives the retrieved context and synthesizes a step-by-step answer, ignoring conflicting outdated information based on timestamp metadata.
5. **Citation:** The Citation Agent annotates the synthesized answer with exact references (e.g., "[1] Deployment Runbook v2, Section 3").
6. **Response:** The user receives a detailed, verified answer with links to the original video timestamp and PDF section.
7. **Feedback (Optional):** If the user finds an issue, they flag it via the UI, prompting the Feedback Agent to log the correction for SME review.
